# Lean Agentic Engineering session contract

Use this harness for real requested work. One lead owns the conversation, scope, integration, ledger and report. Do not create benchmark tasks or require a pilot before delivery.

Read current repository instructions and only the relevant policy/skill. Write a short contract from the user's existing request: one-sentence bar, exclusions, must happen/must never, source pointers, allowed checks and expected results. Do not ask the user to approve routine implementation details already authorized. Retain repository obligations.

Use `local` for local work that does not invoke a PR/adversarial-review delivery process, unless repository policy requires that process anyway. Use `pr` when shipping a PR, running the canonical adversarial review workflow, or where required by the repo. Read the current PR Freeze Bar from its canonical distribution; this file does not modify it. Its repository CI, full baseline evidence for inherited failures, protected assertions and final adversarial pass remain binding. When scope needs a material change, obtain an owner decision.

Keep one session ledger outside the repos and reuse it for follow-ups. Initialize it once with `init`, without numerical allowances. Protect human attention through narrow task boundaries, relevant evidence and stopping when progress needs new authority or causal evidence. The harness does not meter time, model tokens or provider spending.

On a follow-up, compare the request with the frozen acceptance criteria, exclusions and authorized actions. A clarification within that scope continues the current task. A material change starts a new task in the SAME ledger with `start --follows PRECEDING_TASK`, an accurate new contract and its follow-up authorization in `owner_request`. The user's follow-up is the owner decision when it authorizes that change; do not ask again. Retain repository and external obligations. Never edit the old contract, reinitialize the ledger, or hide new requirements in acceptance notes. The successor needs its own checks, assessment and external receipts.

If the request or work contradicts the frozen contract, record `assess --outcome conflict --evidence 'request reference and contradiction'` immediately, including when reconciliation must wait. This permanently prevents the old task from passing; reconcile with a linked successor rather than clearing the declaration. A replaced task remains historical and cannot pass as current completion. The CLI enforces declared conflicts and links, but cannot recognize undeclared semantic contradictions or authenticate the authorization reference. Making that comparison remains the lead's responsibility.

Default to one agent. Delegate only when authorized and useful or required by repository policy. Give specialists a narrow goal, allowed files/actions, clear deliverables, required evidence and stopping condition. Grant no child delegation, merge or deployment authority implicitly. Only the lead writes the ledger and remains accountable for integration and completion. Host permissions and repository rules govern specialist execution; the harness neither spawns nor supervises child agents.

Run approved local checks by name through the harness. A passing command establishes its defined check, not the meaning of every acceptance criterion. Assess the bar with behavioral evidence. Changes invalidate prior results. Missing/blocked/inconclusive checks cannot become PASS. Ordinary PR external receipts are pointers; after actually consulting authoritative CI/independent review evidence, record a PASS receipt with its exact source/revision and `--verified-by`. That declaration records your verification; the CLI cannot authenticate it. Never use it for another agent's unverified green claim. Report local and externally observed evidence clearly.

Stop new work at blocked mandatory validation or access, a proposed weakened invariant, or two failed repair hypotheses. A repeated explanation is not a fresh hypothesis. Park unrelated findings without automatic task expansion, speculative repair campaigns, issues or PRs. Finish authorized cleanup of owned resources. Each check retains its contract timeout and process-group termination. After a lead crash, an unfinished check remains BLOCKED; verify and clean up its owned process before rerunning, without resetting the session.

On pause, create one checkpoint with the next one or two actions. Persist its archive and latest ledger through an authorized durable destination, confirm the returned identity/hash, then record `durable`. Local existence is not proof of persistence. No automatic push for preservation. Resume by comparing actual branch, head and tree fingerprint; preserve contracts, evidence and failed hypotheses. Diagnosis resets the consecutive failure stop only with new causal evidence; history stays in the record.

Write no lesson by default. When a non-obvious verified diagnosis would prevent expensive repetition, search the repo's existing lesson index and update one short note there. Prefer a structural guard or meaningful regression when that captures the actual failure. Do not invent another global memory registry.

Finish with outcome, validation, material limitation and any needed decision. Improve this harness when real work exposes friction, through a separately bounded change. Its executable lives in this package; this session guide is not an installed skill or a second canonical Freeze Bar.
